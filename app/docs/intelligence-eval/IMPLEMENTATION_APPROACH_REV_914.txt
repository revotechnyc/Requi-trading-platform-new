================================================================================
BEST APPROACH — WHY SEQUENTIAL SPRINTS
================================================================================

Do NOT implement the full PDF in one branch. Reasons:

  1. Router/working-set bugs are silent — mixed changes hide regressions
  2. Client demos (Scripts 1–3) are the release gate — protect them every PR
  3. PDF phases have dependencies (snapshot before breadth; calendar before UI)
  4. Phase 4 (trace) touches everything — must be last

Strategy:
  - One sprint = 1–2 weeks
  - One PR = one subsection (e.g. 1.5.a breadth) — 1 to 3 files when possible
  - Exit criteria from IMPLEMENTATION_PHASES_REV_914.txt before next sprint
  - Detailed checkboxes live in IMPLEMENTATION_PHASES_REV_914.txt
  - This file = HOW to execute; that file = WHAT to build

SAFE IMPLEMENTATION PATTERN (copy for every feature)
================================================================================

Step 1 — Read checkbox in IMPLEMENTATION_PHASES_REV_914.txt (e.g. 1.5.a)

Step 2 — Write failing unit test first (or extend existing test file)

Step 3 — Add pure function / formatter in the owning module:
          general-market.ts    → snapshot, health, breadth, VIX, index depth
          stock-discovery.ts   → discovery, movers, ranking
          earnings-day.ts      → calendar, dates, fallback
          market-intent.ts   → new patterns only (minimal)
          NEW file only when module would exceed ~100 lines added

Step 4 — Wire ONE entry point:
          Market features  → tryMarketIntelligenceReply() in general-market.ts
          Earnings         → tryEarningsDayCalendarReply() or data-reply.ts
          Multi-turn       → conversation-context.ts (avoid router unless necessary)
          UI               → Intelligence.tsx + API meta shape

Step 5 — Do NOT rewrite intelligence-router flow in large diffs.
          Early market block (0b) already exists — extend, don't replace.

Step 6 — Run test pyramid (Layers 1–6 above)

Step 7 — Check off checkbox in IMPLEMENTATION_PHASES_REV_914.txt

Step 8 — Update SCORING_SHEET.md for live packs
